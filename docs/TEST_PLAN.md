## 1. 测试原则与门禁

- 公式实现必须先有独立期望值，再写生产代码；禁止用被测函数生成自身期望值。
- 每个公式 ID 至少有正常、边界和异常测试。
- 比较使用明确绝对/相对容差；整数圈数、层数、状态和警告代码必须精确相等。
- 中间步骤与最终结果都测试，避免“最终数值碰巧正确”。
- 所有金样均记录 `calculation_model_version`；模型变更不得静默覆盖旧期望。
- P0/P1 缺陷清零，核心金样、单位、边界、快照/报告一致性测试全绿后方可发布。

## 2. 测试层级

1. 单元测试：单位转换、公式、离散循环、舍入、警告。
2. 模块契约测试：注册字段、输入模型、纯计算、报告上下文和版本。
3. API/Web 集成测试：平台主页筛选契约、模块页面、CSP-safe 文档、安全/缓存头、状态码、JSON schema、数据库事务和读取不重算。
4. 报告测试：HTML 结构、PDF 文本/分页/字体与视觉快照。
5. 数据测试：迁移、约束、备份、恢复、WAL 和磁盘故障。
6. 性能/资源测试：单 worker、并发请求、PDF 限流、内存/磁盘。
7. 工程审核：由机械工程师独立复核公式口径、参数来源和免责声明。

## 5. 边界与非法输入

逐项测试 0、负数、极小正数、软上限、超软上限、NaN、Infinity、数值字符串、超长文本：

- `η=0`、`η>1`；`K_s<1`、`K_b<1`、`K_p<1`、`M<1`。
- `z_max=0`、小数、超过产品上限 100。
- `B=2b`、`B<2b`、`0 < B-2b < p`。
- 超大目标长度导致容量不足，但循环最多执行 `z_max`，不得失控。
- 恰好一层、末层部分圈、末层完整圈、死圈占满第一层。
- 文本包含 HTML/脚本、路径分隔符和 Unicode；报告必须转义，文件路径不可控。
- 八个扩展模块必须在输入模型内预演实际 SI 换算、连乘、乘方和分母；对 `5e-324` 等字段本身为正但会令派生量下溢、除零或成为非有限值的组合统一返回 `422 VALIDATION_ERROR`，不得进入计算器或泄漏为 HTTP 500。该检查是浮点算术安全门禁，不得借机写入未经批准的工程下限。

## 6. 性质测试

在有效域内随机生成输入并验证：

- 各层 `D_j`、每圈长度和累计容量随层号严格增加（圈数相同且 d>0）。
- 固定其他量时，增加面长不会降低容量；增加最大层数不会降低最大容量。
- `capacity_at_actual_layers >= target+termination_allowance`（成功满足时），前一层累计值小于该阈值。
- `n_empty >= n_full`；`i_empty <= i_full`。
- SI 与等价显示单位换算得到相同规范化输入和结果。
- 所有返回数有限，未知结果只用 null。

## 7. API、数据和报告一致性

- POST 响应、GET 快照、HTML 与 PDF 的关键数值及模型版本一致。
- 修改当前配置/默认值后，读取旧记录不改变旧快照。
- 报告渲染器被替换为会调用计算器的测试桩时测试失败，确保禁止重算。
- 模拟数据库写失败：不返回成功 ID；模拟 PDF 失败：计算快照仍保留，报告状态 failed。
- PDF 检查中文字体嵌入/显示、长警告换页、逐层表头重复、页码、免责声明和无截断。
- 新计算必须在 `calculations.release_status`、snapshot schema v4 和 report context schema v4 中保存同一计算时发布状态；改变当前注册表状态后读取旧记录不得漂移。
- 迁移 `005` 对旧行保留 `NULL`，repository 映射为 `legacy_unknown`；不得推断或回填历史状态。
- 遗留 ready artifact 只有在模板版本、受控相对路径、文件大小和 SHA-256 全部匹配时才可下载，并验证 legacy 响应头、HTTP Warning 与文件名前缀。
- `legacy_unknown` 快照没有有效缓存 PDF 时固定返回 `409 LEGACY_RELEASE_STATUS_MISSING`，且测试桩证明未启动渲染器；损坏缓存先标记 failed 后遵循同一 409 路径。
- `/docs` 与 `/redoc` 在严格 CSP 下返回服务端端点清单，不含内联/外部脚本；逐路由验证统一安全头、静态资源一天缓存、计算/报告 `no-store`/`noindex` 及其他响应 `no-cache`。
- 缺固定字体或报告临时目录不可写时启动失败；`/health/ready` 只验证注册表、完整迁移清单、`SELECT 1` 与报告运行目录/字体存在，并明确不调用 `PRAGMA quick_check` 或 PDF 渲染。

## 8. 模块扩展测试

## 9. 性能与资源验收

测试前记录同机既有服务 30 分钟基线。测试环境使用与生产相同容器限制：

- 计算接口：顺序 1000 次及并发 5，总错误率 0；p95 < 500 ms。
- PDF：连续 20 份及并发 5 个请求；实际渲染并发始终 1；p95 < 10 s 或返回受控限流，不发生 OOM。
- Web 容器持续内存不超过 512 MiB，压力结束后无持续增长趋势；不得以大量 Swap 换取通过。
- 数据库、WAL、日志、临时 PDF 和报告目录均受监控；临时文件在失败/超时后清理。
- 压测期间既有服务健康检查连续正常；若 CPU、内存或 I/O 明显恶化，则降低配额/并发再验收。
